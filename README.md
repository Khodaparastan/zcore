# zcore

A modular Zsh framework: structured logging, validation/probes, terminal UI
primitives, an in-memory KV store, an event bus, and an integration layer.

**Version:** see [VERSION](VERSION) (currently 0.6.0)

Modules are versioned independently — `zbase` 3.0.0, `zkv` 4, `zbus` 3 — and
`VERSION` tracks the framework as a whole.

## Quick start

```zsh
# From a checkout — source in dependency order:
source /path/to/zcore/zlog    # logging          (required first)
source /path/to/zcore/zbase   # validation, probes, error codes
source /path/to/zcore/ui      # terminal UI, progress bars (optional)
source /path/to/zcore/zkv     # KV store         (required by z and zbus)
source /path/to/zcore/zbus    # event bus        (optional)
source /path/to/zcore/z       # integration layer
```

Each module is a single sourceable file at the repository root. `z` is
assembled from the part files in [`lib/z/`](lib/z) — those are canonical, and
the root `z` is generated. `zlog` is a symlink into the
[`lib/zsh-log`](lib/zsh-log) submodule, which is maintained upstream.

## Layout

```
z                       Generated by bin/zbundle from lib/z/ — do not edit
zbase ui zkv zbus       Modules — plain sourceable zsh files
zlog                    Symlink into lib/zsh-log (git submodule)
lib/z/                  Canonical parts of z, plus the parts manifest
bin/zbundle             Assembles split modules into their root file
bin/zlint-comments      Header and comment standard linter
tests/unit/<module>/    One suite directory per module under test
tests/integration/      Suites spanning several modules or the build
tests/ztest             Test framework; bootstrap.zsh is the shared fixture
docs/                   Architecture, conventions, API reference
```

### Editing a split module

```sh
$EDITOR lib/z/cache.zsh     # parts are canonical
make bundle                 # regenerate the root module
make test
```

`source lib/z/z.zsh` loads the parts directly, so a change is testable before
bundling. `make lint` and `make install` refuse to proceed when a generated
root file has drifted from its parts.

## Development

```sh
make bundle        # assemble split modules from lib/<module>/
make bundle-check  # fail if a generated module has drifted from its parts
make test          # run every suite
make test-unit     # tests/unit/ only
make test-module M=zkv
make lint          # syntax, bundle drift, and comment standard
make lint-style    # header and comment standard only (docs/conventions.md)
make install       # install to ~/.local/share/zcore
```

Every suite loads the modules it exercises itself, so it also runs on its own
— `zsh tests/unit/zkv/test_zkv_tx.zsh`, optionally with a test-name pattern.
The runner accepts the same selectors as the make targets, plus `-t` to filter
by test name.

See [docs/architecture.md](docs/architecture.md) and
[docs/conventions.md](docs/conventions.md); per-module API references live in
[docs/api/](docs/api).
